Netormium 1.0.0-rc18 — RC18 validation

Release objective:
- Stop repeating automatic ECJ download attempts as the primary workflow.
- Configure a locally installed Java ME SDK/WTK and locally supplied ECJ only
  after validating the actual toolchain inputs.

Implemented:
- Added gateway/scripts/configure-local-toolchain.js.
- The helper locates CLDC/MIDP API archives and the host-specific preverifier
  under an explicit SDK root.
- It inspects required API class entries using the JDK jar tool.
- It verifies the supplied ECJ artifact using the pinned SHA-512 and batch
  compiler legacy -1.3 launch probe.
- It writes build.properties only after every required component passes.
- It refuses incomplete SDKs, non-executable preverifiers, invalid API archives,
  and missing/unverified ECJ; no partial properties file is left behind.
- Added four tests covering CLI parsing, successful configuration, rejection
  of invalid SDK inventories, and refusal to silently fall back to javac.
- Updated Gateway and all three Java ME User-Agent identities to RC18.
- Updated README, changelog, and toolchain acquisition documentation.

ECJ JAR, or access to a host environment where these can be obtained.
